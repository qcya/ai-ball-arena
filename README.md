# AI Ball Arena · 球球竞技场

青春沿岸的六模型球球脚本对战项目。**观战画面 v0.8：固定六人列表、简洁比赛计时与扩大地图；玩法规则沿用 v0.6**。初次打开没有内置 AI、没有自动补位的陪练。每位模型一次会话交付三份 JavaScript 文件，比赛时只执行你导入的当前模式脚本。

## 本次规则更新

个人赛和缩圈赛改为最后存活者胜、淘汰不复活，名次按淘汰先后；质量仍决定体型、吞噬和速度，但不是个人胜负分数。团队到时比全队总质量，并可通过团灭敌队提前胜。
移速按每颗分身：240及以下100%，264约98.56%，480为90%，960为81%；连续衰减，无固定最低速度。初生绝对速度保持旧版手感，不把示例100%误改为100世界单位/秒。

API仍为1.0、席位顺序和导入登记不变；本版没有修改参赛者源码。旧脚本能加载不等于它知道新目标：主办人应把同版AI_TASK.md给所有重新参赛模型。保留旧稿归档，这次因统一规则变更重新征稿，不记作旧版本技术重试。不要只更新其中一位而让其余选手按旧规则比赛。

## 最短流程

1. 把 **[AI_TASK.md](AI_TASK.md)** 或仓库链接发给参赛模型，要求一次交出 `solo.js`、`team.js`、`storm.js`。文件任务书也内置于游戏，可以点“下载统一 AI 任务书”。它不是联网 API，不需要任何 API Key。
2. 用 Edge / Chrome 打开本仓库根目录 `index.html` 或 `球球竞技场.html`。点击对应模型卡片“导入 .js 文件”，可一次选择三份。程序根据代码中 `mode` 自动分配。
3. 给第二位模型重复一次，点“开始当前模式”。只导入两位就只有两位，其他四个席位不出现。顶部切换个人、团队、缩圈，自动加载相应文件。

也可以只导入一个模式先测；缺哪个模式就不参加那个模式。纯观战是默认。要亲自玩，勾选“我也入场”，选一个图标；此席位由人控制，不会同时执行该席位脚本。单人可测试，团队正式对抗要求偶数人数：2人1V1、4人2V2、6人3V3，均随机分队。切换模式会重开一局。

**初稿政策：** 首份可运行脚本锁定，不允许按成绩改策略。仅导入/语法/接口/执行错误最多允许每位模型一次修复；记录初次与修复状态。游戏只能限制本页重交，不能判断外部会话是否偷偷迭代，主办人还应保留原始对话和模型版本。手动“新建测试批次”会清空文件与计数，不应把它当成正式比赛无限重试。关闭/刷新网页会丢失导入文件，保留好原始三个 .js 文件。

## 操作与画面

WASD / 方向键移动，左键按住吐球，右键单次分裂，空格按住向鼠标位置聚拢。每颗分身以自己的圆心瞄准鼠标；普通攻击鼠标静止800ms或离开画布后回退八向键盘方向。聚拢不因鼠标静止而改成重心，空格不触发吐球或分裂。合并仍需8秒冷却。P暂停、V镜头、T工具、H纯净画面、滚轮缩放。纯AI观战时手动操作无效。

物理60Hz、显示补间保留。普通食物静音，关键事件有原创合成音效，无背景音乐。测试工具仅用于勾选人类入场后的机制试验；不在纯AI比赛中偷偷生成或加强选手。

## 已实现的关键机制

- 单颗判定：吃玩家球要达到该颗质量的1.2倍并足够覆盖；不能拿所有分身总和当体积。
- 分裂：80起，质量平分，最多16颗；8秒后靠近合并。
- 吐球：单颗30起，每次吐10；质量球可被任意满足条件的选手吃掉，自己0.5秒后可回收。无定时消失，可囤积诱敌再回吃，但可能被抢，也会被毒圈删除。
- 吃刺：单颗120起、有3个空分身位，**400→4×120=480，总质量+20%**。风险来自四分，不再扣质量。
- **队友可吃分身：被吃的队友还有多颗时可转移其中分身；只剩最后一颗时禁止队友吞掉。** 同一帧也保留最后一颗，接受方可以只有一颗。仍需1.2倍质量、覆盖、出生保护检查，不增加击杀或全队总质量。吐出的质量球同样能喂队友。
- 个人/缩圈：无复活，最后存活者立即胜；按淘汰先后、同帧并列。180秒到时仍多人存活则“未分胜负”，不拿质量硬判冠军。全员死亡无冠军；零/单选手为测试。
- 团队：到时比较全队总质量，整队被消灭提前输。未团灭时队员死亡3秒后复活。相同总质量或双方同帧全灭为平局。
- 缩圈：圈外每颗掉质量至0，圈外食物/质量球/刺球清除；圈外不能囤粮。
- 连续移速：按每颗当前质量，初生速度封顶，每翻倍乘0.9，吐球/分裂变轻加速、吃回/合并增重减速；分裂冲刺另算。手动面板显示相对移速（多分身显示范围）。

完整可直接交给AI的规则和动作字段见 [AI_TASK.md](AI_TASK.md)，源码规则在 [RULES_AND_INTERFACE.md](RULES_AND_INTERFACE.md)。

## 运行器、错误与回放

脚本在独立 Worker 中执行，外层使用不带同源权限的 sandbox iframe，CSP禁联网。观察以副本传入，动作只接受白名单字段。20Hz决策、统一3tick延迟与共同提交屏障；加载限时2秒、单次决策往返等待预算100ms（包括消息排队与校验，不等于只计act函数CPU时间）。一次错误停止该脚本，其他选手继续，不自动换成陪练。

导出“错误 / 提交报告”，把技术错误交给原模型修一次。脚本初次导入会做接口冒烟检查，但跑得通不等于策略强，也不保证以后所有局面都不报错。报告记录文件校验值、模式、重试和错误；支持安全上下文时使用SHA-256，否则标明FNV-1a，不冒充密码学哈希。

回放记录实际动作、名单、分队种子和提交记录，不依赖脚本再次执行。引擎版本 `0.6.0`；旧版回放用旧版播放器。不要把运行等待时间当游戏时间。

**边界：** 这不是操作系统级恶意代码沙盒；浏览器不能可靠硬限制任意JS堆内存。只导入自己信任的模型生成文件，不要用主浏览器批量运行陌生人投稿。CLI检查器同样不适合恶意代码。

## 项目结构与检查

`src/engine.js` 为权威物理；`agent-api.js` 为版本化接口；`agent-runner.js` 为隔离与调度；`agent-lobby.js` 为导入和重试登记；`app.js` / `render.js` 为画面、输入适配、回放。`src/bots.js` 仅留作旧回归测试，不打包、不自动运行。`examples/` 是三个**故意不行动的接口样例**，不是参赛策略。

运行游戏无需安装依赖；改源码后使用 Node.js20+、Python3：

```sh
npm test
npm run soak
python3 build.py
node tools/check-agent.cjs examples/solo.js examples/team.js examples/storm.js
```

当前浏览器检查（另需Python Playwright与Chromium；可用CHROMIUM_PATH指定可执行文件）：

```sh
python3 tests/browser_runner_v05.py
python3 tests/browser_lobby_v05.py
python3 tests/browser_errors_v05.py
python3 tests/browser_visual_v05.py
python3 tests/browser_results_v06.py
python3 tests/browser_speed_v06.py
```

`browser_v03.py`、`browser_v04.py`和对应报告是历史版本回归记录，不作为当前入口验证。脚本决策时限与画面FPS受硬件负载影响，测试结果不代表所有电脑都能达到同一帧率。

## 0.6.1 观战与稳定性修订（物理仍为 0.6.0）

- 横屏左侧为完整游戏场地，右侧是只读监控栏，显示六位选手状态、各队质量、存活数、FPS、事件和小地图。`H` 纯净画面仍可隐藏面板。
- 没有更改质量、分裂、吃刺、毒圈、队友吞噬、胜负、物理 60Hz 与策略 API 1.0；也没有改任何第三方参赛脚本。
- 过去浏览器侧在收到策略结果前开启 100ms 墙钟计时，排队、Worker 消息传输也可能算入，容易在主机繁忙时误杀。现在 100ms 是性能建议值，实测慢决策只计数告警；**1 秒无响应**仍终止，以防死循环。两种阈值对全部参赛者一致。
- 六个 Worker 同步屏障在响应慢时会暂停物理。观战模式根据最近等待时间自动降低所有选手的统一**墙钟演示速率**，尽量消除“走三步停一下”；虚拟游戏时间的步长、顺序、行动延迟、物理与回放记录不变。录像回放仍按照固定 60Hz 播放。
- 渲染层对快速变向添加很短的平滑视觉缓冲，**不修改世界坐标或任何对战判定**。所以策略自身频繁反向仍可能使球在附近徘徊，这不能通过改显示变成聪明策略。
- 用户提交的 6 位选手仅打包于单独提供的本地观战演示，不随此公开项目的主仓库发布。Gemini 为展示用席位名称，脚本内部著作说明不作为游戏机制或胜负依据。

**运行复核：** `npm test`；`npm run soak`；`python3 build.py`。显示 UI 可用 Playwright 验证；策略冒烟测试只证明 API 合法，不代表正式对抗胜率。

## v0.7 · 纯净横屏录制画面

- 直播画面隐藏原顶部导航、左下控制条、开发工具和画面四角坐标；只保留左侧赛场、右侧比赛名称与倒计时、实时选手列表和全场小地图。
- 选手列表**仅作实时展示**：存活者在前、按当前质量降序；出局者自动移到最后。个人赛/大逃杀的正式胜负依然取决于最后存活/淘汰顺序，超时且多人存活不会据质量私自决定冠军。
- 大逃杀是 `storm` 模式的**显示名称**，底层 `mode:'storm'`、策略 API 1.0、三个比赛脚本和碰撞规则均未改变。
- 导播相机依据所有存活选手的全部分身位置，动态计算包围范围并平滑移动、缩放；分散时尽量全景，集中时自动拉近。按 **V** 可以切换自动导播与全场镜头，滚轮可以在比赛中调整缩放。
- 小地图整图显示所有存活分身的**图标**、刺球及毒圈边界，不绘制普通食物。主画面结算改用轻量冠军字幕，避免传统结果弹窗盖住视频。
- 直播画面不显示切换模式按钮。按 **L** 打开独立的选手/模式设置页，或在原设置页选择个人赛/团队赛/大逃杀。设置页不会出现在正常赛场录制画面中。
- 渲染仍由浏览器 `requestAnimationFrame` 按实际屏幕刷新率驱动，设备和浏览器允许时可显示高刷新率平滑插值；**不保证稳定 240 FPS**，物理仍为固定 60Hz、脚本决策仍为 20Hz，以保证已提交策略和重放兼容。**尚未执行 4K/120fps 视频导出**，须先由主办者确认界面。
- 仓库只包含空白可导入的比赛引擎；本地演示包中的六位选手代码属于本次参赛素材，未默认上传到仓库。

## v0.9 · 视频中的模型称呼

场内球体仍只显示品牌简称；右侧列表固定显示完整的**节目席位型号名称**，没有选手编号。其作用是让观众区分六名角色，而不是宣称代码作者身份已被第三方验证。特别说明：**Gemini 展示席位使用 GPT-5.6 代写的代码**，并非 Google Gemini 模型实际编写。其他席位的展示型号也不构成独立真实性认证；正式对外发布“模型编程实力比较”应另附原始会话和型号证明。
